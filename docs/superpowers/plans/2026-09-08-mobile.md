# Headboard Mobile Implementation Plan (Expo / React Native)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The iOS screen of the prototype (402×874) as an Expo app that also runs on Android, reusing `@headboard/core` and the token set.

**Architecture:** Expo SDK 52 app in `apps/mobile` inside the npm workspace (metro `watchFolders` for `packages/core`). Tokens as a `light`/`dark` object served by `ThemeContext`; every style reads `t.<token>`. Screens are switched by a custom tab bar (no navigator: the prototype has one level). Sheets are `Modal`s with a `sheetUp` translate animation. zustand store mirrors the web store (persist via AsyncStorage, key `headboard-v1`).

**Tech Stack:** expo ~52, react-native 0.76, expo-font + `@expo-google-fonts/golos-text` + `@expo-google-fonts/ibm-plex-mono`, react-native-safe-area-context, @react-native-async-storage/async-storage, expo-document-picker, expo-image-picker, zustand.

**Spec:** design spec §Mobile + README §iOS; prototype markup lines 620–913 of `Headboard.dc.html`.

## Global Constraints
- Same token names as web (`tokens.ts` exports `light`, `dark`, `Tokens`); no literal colours in components except the always-dark file preview (`rgba(32,29,23,.9)`, `#F2EDE4`, `rgba(245,242,234,.3/.28/.12/.7)`) which the README fixes.
- Fonts: `GolosText_400Regular/500Medium/600SemiBold`, `IBMPlexMono_400Regular/500Medium/600SemiBold`.
- Radii: segments/chips 7, cards 14, buttons 9–10, sheets 22, inputs 10–12.
- Android uses the identical UI; only safe-area insets differ.
